## How I approach engineering

- **Understand the mechanism.** Use first-principles implementations to learn what abstractions do under the hood.
- **Measure, don't guess.** Establish baselines, choose relevant metrics, and document limitations instead of relying on a single headline score.
- **Build end to end.** Connect data preparation, training, evaluation, and a usable interface where the problem calls for it.
- **Keep claims auditable.** Separate implemented capabilities from experimental work and future plans.
- **Learn in public.** Improve through documentation, code review, and open-source collaboration.
